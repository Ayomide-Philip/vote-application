# PRD Examples Directory

This directory provides concrete, reference implementations of Product Requirements Documents (PRDs) generated by the `prd` skill.

These examples illustrate how output structure, detail level, and validation depth adapt across the three scope tiers:

---

## Example Catalog

| File                                                                           |     Tier     | Context                    | Best Used For                                                                                                             |
| :----------------------------------------------------------------------------- | :----------: | :------------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| [`01-light-tier-example.md`](./01-light-tier-example.md)                       |  **Light**   | Greenfield CLI / Micro-App | Small scripts, single-purpose CLI utilities, quick prototype features. No heavy governance.                               |
| [`02-standard-feature-spec-example.md`](./02-standard-feature-spec-example.md) | **Standard** | Existing Codebase Feature  | Adding a distinct capability (e.g., API key management) to an existing product without duplicating root context.          |
| [`03-full-tier-prd-example.md`](./03-full-tier-prd-example.md)                 |   **Full**   | Multi-Role Greenfield SaaS | Large platforms, multi-tenant systems, enterprise apps with strict RBAC, data schemas, API contracts, and MoSCoW scoping. |

---

## Scope Tier Comparison Matrix

| Aspect                      | Light Tier (`01`)          | Standard Tier (`02`)                  | Full Tier (`03`)                                           |
| :-------------------------- | :------------------------- | :------------------------------------ | :--------------------------------------------------------- |
| **Typical Target**          | Small feature / simple app | Feature in existing codebase          | Full multi-role product                                    |
| **Document Destination**    | `PRD.md` or inline         | `docs/<feature-name>.md`              | `PRD.md` in repository root                                |
| **Governance & Versioning** | Minimal (title + date)     | Core metadata & release milestone     | Strict semver (1.0.0), status, changelog                   |
| **Functional Requirements** | `FR-001` with Gherkin AC   | `FR-FEAT-001` with rules & AC         | `FR-001` with rules, dependencies, AC                      |
| **UI/UX Coverage**          | Primary flow only          | Modified components & 4-5 UI states   | Screen inventory, design tokens, 5 UI states               |
| **Technical Specs**         | Brief stack statement      | Schema delta & modified API endpoints | Complete TypeScript models, API contracts, latency budgets |
| **Prioritization**          | Implicit in scope          | Feature rollout checklist             | Full MoSCoW (Must, Should, Could, Won't)                   |
| **Review Gate**             | Fast 5-point verification  | 8-point core audit                    | Exhaustive 9-point audit & traceability                    |
| **User Approval Gate**      | **Required**               | **Required**                          | **Required**                                               |
